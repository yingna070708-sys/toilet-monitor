# Toilet Cleanliness Monitoring System

A college-wide toilet cleanliness check-in/check-out system built with plain PHP (PDO/MySQL) and Bootstrap 5. No framework or build step required — just PHP + MySQL + Apache/Nginx.

## Features

**Admin**
- Add / edit / delete (deactivate if it has history) student & admin accounts
- Add / edit / delete toilets
- Assign one or many toilets to each user (many-to-many)
- View complete history of every toilet: check-in/out time, photos, comments
- Filter history by toilet, student, date range, and status

**Student / User**
- Logs in with a username created by the Admin, sets their own password on first login
- Can change their password anytime
- Sees only the toilet(s) assigned to them — auto-opens if only one is assigned
- Check-In: records timestamp automatically, allows multiple photo uploads + comment
- Check-Out: only allowed if the student has an active check-in for that toilet
- Can see the shared history of a toilet (all past check-ins/outs by anyone assigned to it)

## Database design

```
users            (admin + student accounts)
toilets          (master list of toilets)
user_toilets     (many-to-many: user_id <-> toilet_id)
toilet_sessions  (one row per visit: check-in + check-out fields, status)
session_photos   (many photos per session, tagged 'checkin' or 'checkout')
```

Key business rules enforced in `includes/functions.php`:
- A student **cannot check in twice** to the same toilet while an earlier check-in there is still active (`do_checkin()`).
- A student **cannot check out** unless they already have an active check-in for that toilet — this is checked server-side against the database, not just the UI (`do_checkout()`).
- Once a session is checked out (`status = 'completed'`), there is **no edit/delete UI for it anywhere** in the app — it remains as a permanent history record. Admin/user "delete" actions on toilets/users with existing history deactivate them instead of removing rows, to preserve the audit trail.

## Setup

1. Create a MySQL server/database access (e.g. via XAMPP, WAMP, or a real host).
2. Copy this whole folder to your web server's document root (e.g. `htdocs/toilet-monitor`).
3. Edit `config/db.php` with your MySQL host/username/password.
4. If you're hosting in a sub-folder (e.g. `/toilet-monitor`), set `BASE_URL` in `config/config.php` to match (e.g. `'/toilet-monitor'`). Leave it as `''` if hosted at the web root.
5. Open `http://yourserver/toilet-monitor/install.php` in your browser. This will:
   - Create the database/tables from `schema.sql`
   - Ask you to set the Admin password and create the `admin` account
6. **Delete `install.php`** from the server once setup is done (it's a one-time script).
7. Log in at `login.php` with username `admin` and the password you chose.

### Manual setup (alternative to install.php)
```sql
mysql -u root -p < schema.sql
```
Then create the admin account manually with a bcrypt hash generated by `password_hash()` in PHP, since a hardcoded hash cannot safely be provided in advance.

## Folder structure

```
config/         DB + app configuration
includes/       auth, shared functions, header/footer
admin/          Admin dashboard, user/toilet management, assignments, history
user/           Student dashboard, toilet check-in/out, personal + shared history
uploads/        Uploaded check-in/check-out photos (auto-created, PHP execution disabled)
schema.sql      Full database schema
install.php     One-time browser installer (delete after use)
```

## Notes for production use

- Run over HTTPS so login credentials and session cookies are protected.
- The uploads folder has a `.htaccess` blocking script execution — keep this if you host on Apache; add an equivalent rule if you use Nginx (`location /uploads/ { location ~ \.php$ { deny all; } }`).
- Consider adding a cron job or admin action to auto-close/report sessions left "active" for an unusually long time (not included, since it's a judgment call: e.g. a toilet manager may want to manually query and follow up rather than auto-close).
- Photo files are validated by real MIME type and size-limited (default 8MB/photo, 10 photos/submission) — adjust in `config/config.php`.
